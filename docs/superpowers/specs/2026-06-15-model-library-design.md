# 模型库功能设计

## 目标

在左侧零件库配置栏中增加模型库能力。用户可以在零件树和模型库之间通过 Tab 切换；从模型库拖拽在线模型到设计区后，渲染器显示加载提示并把模型作为新物件加入当前场景；用户也可以从模型库入口上传本地模型文件并加入当前场景。

首版支持本地 `glb`、`gltf`、`obj` 三种格式。在线模型库先使用 mock 数据，并预留后续替换为接口数据的边界。

## 用户体验

左侧栏保留现有宽度和视觉结构，顶部增加 Tab：

- `零件树`：保留现有模型层级、虚拟列表、选择逻辑。
- `模型库`：展示 mock 模型列表，每项包含模型截图、名称、分类、格式。模型项可拖拽，也可点击添加。

模型库顶部提供 `添加本地模型` 按钮，打开文件选择器。上传或拖拽期间，设计区复用现有加载遮罩显示模型加载状态。加载成功后，新模型自动选中，左侧零件树刷新；加载失败时显示现有错误提示。

## 数据边界

新增 `src/lib/model-library.ts`：

- `ModelLibraryItem`：定义 `id`、`name`、`category`、`format`、`url`、`thumbnailUrl` 等字段。
- `modelLibraryItems`：首版 mock 列表。
- 后续接接口时，可以把 mock 列表替换为异步数据源，UI 和渲染器调用保持稳定。

拖拽使用 `DataTransfer` 存储 JSON，包含模型库条目的必要字段。渲染区只接受明确的模型库拖拽数据，避免和普通文件拖拽混淆。

## 渲染器接口

`ThreeEditor` 新增新增模型接口：

- `addModelFromUrl(url, options)`：加载在线模型库条目。
- `addModelFromFile(file, options)`：加载本地文件。

这两个接口不会替换当前场景。若当前没有根模型，则创建一个编辑根组作为 `modelRoot`；新增模型作为子对象加入根组。新增模型需要经过和整屋模型相同的基础处理：材质适配、阴影配置、对象 ID 初始化、对象映射刷新、天气效果刷新、选择状态更新。

现有 `loadModel` 和 `loadModelFromUrl` 继续作为“替换整屋模型”的入口，供顶部上传和示例加载使用。

## 格式支持

- `glb` / `gltf`：复用 `GLTFLoader` 和已有 DRACO 配置。
- `obj`：使用 Three 官方 addon `OBJLoader`，不新增 npm 依赖。

本地上传入口的 `accept` 扩展为 `.glb,.gltf,.obj`。格式校验同时更新为三种格式。

## 错误处理

不支持的文件格式直接在 App 层提示。加载失败时保留当前场景，不清空现有模型。在线模型缺少 URL、请求失败或解析失败时，显示错误信息并结束加载状态。

## 测试与验证

新增或调整单元测试覆盖：

- 模型库 mock 数据字段合法。
- 支持格式判断覆盖 `glb/gltf/obj` 和不支持格式。

手动验证：

- `npm test`
- `npm run build`
- 启动本地开发服务后验证：Tab 切换、模型库拖拽到设计区、点击添加在线模型、本地上传 `glb/gltf/obj`。
